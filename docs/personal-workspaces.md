# Личное пространство и организации

## Модель продукта

У человека один аккаунт StaffHub. После регистрации ему сразу доступно личное
пространство, без приглашения и без автоматически созданной организации.
Организации подключаются к тому же аккаунту по желанию; их может быть несколько.
Переключатель показывает «Личное пространство» и доступные пользователю компании.

| Возможность | Личное | Организация |
| --- | --- | --- |
| Диалоги, группы, сообщения, вложения, голосовые, видеосообщения | Да | Да |
| Сохранённые сообщения | Свои | Отдельные для каждой организации |
| Поиск собеседника | По нику или точному полному email | По нику, имени или email среди сотрудников |
| Звонки, история звонков, поиск сообщений и файлов | В рамках личного пространства | В рамках выбранной организации |
| Каналы, проекты, задачи, роли, отделы, аудит | — | Да |

`PERSONAL` в существующем API обозначает диалог один на один. Его принадлежность
определяет `organizationId`: `null` — личный диалог, UUID — рабочий.
Поэтому с одним человеком можно иметь два независимых диалога: личный и рабочий.
Переключение пространства не требует выхода из аккаунта.

## Реализация и границы доступа

- `users` остаётся общей учётной записью; `organization_members` хранит членство и
  роль отдельно от личного аккаунта. Дублировать пользователей по типу аккаунта
  или создавать фиктивные организации не требуется.
- `chats.organization_id` и `files.organization_id` допускают `NULL`. Отсутствующий
  `orgId` в списках чатов, файлов, истории звонков и поиске всегда означает личное
  пространство, а не выборку из всех организаций.
- Чат открывается только его действующему участнику. Для рабочего чата дополнительно
  проверяется текущее членство в организации. Администратор компании не получает
  доступ к чужим личным диалогам или закрытым рабочим чатам через поиск и файлы.
- Добавлять людей в групповой чат может его администратор. Рабочий чат допускает
  только участников своей организации. Состав диалога один на один не расширяется.
- Загрузка личного файла не требует организации. До отправки он доступен только
  загрузившему пользователю; после отправки — участникам чата. Файл нельзя
  прикрепить к сообщению из другого пространства. Скачивание по выданной ссылке
  повторно проверяет доступ, в том числе после удаления сотрудника из организации.
- Удаление сотрудника отзывает его участие в рабочих чатах и подписки WebSocket.
  Личные группы, сообщения, файлы и аккаунт сохраняются. Повторное вступление
  подключает сотрудника к общему чату, но не восстанавливает все закрытые чаты.
- Создание диалога и сохранённых сообщений выполняется в транзакции с блокировкой
  по паре участников и пространству: одновременные запросы не создают дубликаты.
- Новые чаты доставляются участникам через WebSocket. Клиенты помещают их только
  в соответствующее выбранное пространство. Ссылки на чат открывают его пространство
  после серверной проверки доступа.
- Выбранное пространство запоминается на устройстве отдельно для каждого пользователя.
  Новый пользователь начинает в личном. Недоступная сохранённая организация не выбирается.
  При переключении очищается список чатов и пересоздаются экраны; при выходе очищаются
  кеши сообщений и файлов. Уведомления и входящие звонки доступны на уровне аккаунта.

## Переход существующих данных

Миграция `1763000000001-AddPersonalWorkspaces` разрешает личные чаты и файлы,
добавляет индексы и ограничение типов личных чатов. Существующие UUID организаций,
переписка, файлы, роли и приглашения сохраняются. Старые рабочие диалоги не переносятся
в личное пространство; сохранённые сообщения организации также остаются рабочими.

Применить миграции перед запуском обновлённого API и клиентов:

```sh
pnpm --filter @corp/api db:migrate
```

Откат миграции разрешён только пока личных чатов и файлов нет. Если личные данные уже
появились, `down` останавливается с ошибкой, сохраняя их. Ранее выданные ссылки
скачивания без идентификатора пользователя нужно получить заново.

## Проверка

Для Windows есть полностью изолированный прогон: нужны Node.js, установленные
зависимости проекта и запущенный Docker Desktop.

```powershell
powershell -File scripts/test-personal-workspaces.ps1
```

Скрипт поднимает отдельные PostgreSQL, Redis и MinIO на свободных локальных портах,
применяет все миграции, запускает API и проверяет сценарии через HTTP и WebSocket.
В конце он останавливает свой API и удаляет только свои тестовые контейнеры и данные.
Рабочая база и `.env` не изменяются. Логи остаются в `.codex-temp`.

Для уже запущенного одноразового тестового API:

```powershell
$env:STAFFHUB_TEST_API = 'http://127.0.0.1:5300/api'
node --test apps/api/test/personal-workspaces.e2e.cjs
```

Проверяются регистрация без организации, повторная регистрация, уникальность и смена
никнеймов, поиск по нику и точному email, миграция существующих аккаунтов,
дубликаты диалогов при конкуренции, личные группы, доставка сообщений, рабочие
приглашения, общий чат, изоляция списков/поиска/вложений/звонков, доступ администратора
и отзыв членства с сохранением личной переписки.

Остаются прежние ограничения: на мобильном звонки поддерживаются в диалогах один
на один; полноценные групповые звонки доступны в вебе. Мобильный интерфейс проверяется
компилятором TypeScript, а прогон на устройстве требуется перед выпуском мобильной сборки.

## Дальнейшее развитие

Уникальные никнеймы и поиск по ним описаны в [отдельном документе](usernames.md).

Следующими отдельными улучшениями могут стать QR-контакты, запросы на
переписку от незнакомых людей, блокировки и жалобы, подтверждение email и ограничения
частоты регистрации/сообщений для открытого публичного запуска. Они не меняют модель
одного аккаунта с независимыми пространствами.
